# Настоящий ModSecurity + OWASP CRS

Настройки находятся в `waf.env`. Образ и digest закреплены в `compose.yaml`. Никаких Flask-проверок, имитирующих WAF, и собственных WAF-правил нет.

`BACKEND=http://vulnerable:5000` направляет запросы 8081 в тот же процесс и SQLite-том, что обслуживает 8080. `MODSEC_RULE_ENGINE=On` включает блокировки; `MODSEC_REQ_BODY_ACCESS=On` включает проверку POST-форм. Стандартный CRS работает на paranoia level 1 с inbound threshold 5.

`MODSEC_RESP_BODY_ACCESS=Off` — явная настройка эксперимента: исследуем входящие запросы, особенно POST Stored XSS. Фильтрация ответа не должна скрывать факт сохранённой инъекции. WAF не удаляет строки из БД. Перед каждым сценарием очищайте общий тикет командой `scripts/lab.ps1 clean-comments`.

Audit в Native/Serial пишется в stdout, части ABFHZ содержат запрос/URI, ответ/статус и сообщения с ID правил. Тело POST и пароль в audit намеренно не сохраняются; причина срабатывания и URI с `lab_case` позволяют сопоставить запрос. Журналы могут содержать тестовые cookies и фрагменты matched data; в стенде используются только искусственные учётные записи.

`scripts/lab.ps1 logs` сохраняет реальные журналы в `logs/waf.log`. `tests/check_waf_logs.py` связывает пять заблокированных запросов из `http-waf.json` с транзакциями audit, требует 403 и сообщения детектирующего правила (одного только anomaly evaluation недостаточно). Поддерживаются Native-разделители ModSecurity v2 и v3. IDOR проверяется отдельно и не должен блокироваться искусственным правилом по номеру заявки.

**Текущее состояние на 22.10.2026:** WAF запущен. Полный `scripts/lab.ps1 test` дал 54/54 HTTP и 5/5 audit PASS. Фактические детектирующие правила: SQLi 942100; оба XSS 941100/941110/941160/941390; Command Injection 932235; Path Traversal 930110. Во всех пяти транзакциях есть итоговое 949110. IDOR через WAF возвращает 200. Подтверждения: `reports/generated/waf-evidence.json`, `logs/waf.log`. Это результаты выбранных запросов, а не доказательство блокировки всех вариантов атак.

После пересборки backend старый nginx может удерживать прежний IP; при первой проверке он обратился к fixed, что выдало cookie nexus_fixed и неожиданный 403 IDOR. Команды start/test теперь пересоздают весь стенд через `--force-recreate`, сохраняя тома; после этого 8081 снова обслуживает vulnerable. Настройки фильтрации и правила не менялись. Сеть lab: internal=false; порт WAF опубликован только как 127.0.0.1:8081:8080.

Источник параметров: [официальный README образа OWASP CRS](https://github.com/coreruleset/modsecurity-crs-docker). Доступность выбранного тега первоначально проверялась через Docker Hub API; запуск и блокировки теперь подтверждены отдельно в VERIFICATION.md.

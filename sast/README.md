# Конфигурация статического анализа

- `sonar-vulnerable.properties`, `sonar-fixed.properties`: два независимых проекта Community Build. Анализируется только соответствующее приложение; отчёты и тестовые payload не входят в область анализа.
- `registry-python.yml`: **неизменённый ответ официального Semgrep Registry** `https://semgrep.dev/c/p/python`, получен 21.10.2026. JSON является допустимым YAML; файл содержит 151 готовое правило. Это сторонние правила, не авторские. Их source, references и license сохранены в metadata каждого правила. Применяется [Semgrep Rules License v1.0](https://semgrep.dev/legal/rules-license). Используется для локального анализа этого учебного проекта.
- `lab-rules.yml`: четыре собственных учебных правила. Ищут SQL-интерполяцию перед execute, вызов с `shell=True`, отключение Jinja-экранирования и поток ввода к `send_file`. Не используют названия файлов приложения, номера строк или учебные комментарии для обнаружения.

Результаты групп сохраняются раздельно: `semgrep-{app|app-fixed}-{registry|custom}.{json,sarif,log}`.
Зафиксированный snapshot позволяет повторять анализ без обращения к Registry. Метрики и проверка обновлений отключены, используется `--oss-only`. Ноль находок означает лишь отсутствие совпадений с выбранным набором правил в этой области анализа.

Скрипт не использует `--error`: найденная уязвимость не является техническим сбоем сканирования. Он отдельно проверяет exit code, ошибки разбора и наличие реально просканированных файлов. Любая техническая ошибка даёт FAIL и ненулевой код.

Фактический результат первого запуска: готовый набор — 0/0 находок; собственный — 5/1. Оставшееся предупреждение о пути в исправленной версии разобрано в `reports/TASK-2-SAST.md`. IDOR определяется проверками двух пользовательских сессий и ручным обзором прав; собственного искусственного правила для него нет.
